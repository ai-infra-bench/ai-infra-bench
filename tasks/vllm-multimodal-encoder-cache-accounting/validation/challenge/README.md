# Independent encoder-cache challenges

These curator-only checks live outside the agent image. `challenge_encoder_cache.py` exercises real request construction, scheduler admission, encoder writes, cache reuse/eviction and ordered partial reads across sparse, dense, empty and speculative-lookahead windows. Only media production and inference tensors are supplied by the fixture. Cold nonempty items require their entire output budget; empty windows can advance without encoder resources.

`challenge_encoder_capacity.py` independently exercises the real scheduler `compute_encoder_budget` and runner `MultiModalBudget` consumers. Its media geometry is 137 prompt positions with nine rows, 53 with five rows, a dense eleven-row item, an all-false seventeen-position item and an empty item. The real SchedulerConfig constructor uses a two-token decoder batch, and expected capacities retain that configured floor. Registry defaults and internal accessor choices are unrestricted: the challenge observes the capacities actually used by scheduler and runner, without making an unused diagnostic accessor call.

Run both scripts inside the pinned task image after applying the selected control. The cache challenge emits structured results plus `CHALLENGE_ENCODER_CACHE=PASS|FAIL`; the capacity challenge emits structured results and exits zero only if every consumer capacity is correct. A combined state passes only when both scripts pass. Oracle, dense-cache, direct-count, request-initialized-count and preserved Astra alternatives should pass; Base and the isolated scheduler/runner capacity regressions should fail. Actual commands, hashes and outcomes are recorded in e2e-evidence.json.
