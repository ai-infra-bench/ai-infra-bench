# Let the model manage its working context in Pi

I use Pi for long-running tasks that explore several approaches. I want the model to save working notes, start a fresh context window, and continue the same task. It should be able to reset early, receive a reminder when space runs low, and have Pi reset automatically at the configured limit.

Implement an optional extension at `packages/coding-agent/examples/extensions/context-management/index.ts`, using local persistent storage and ordinary API-key providers without a hosted notes/history service. Keep normal Pi behavior unchanged when disabled. While enabled, capacity-driven resets replace Pi's ordinary summarizing compaction.

Give the model guidance to save the task goal, relevant user instructions and corrections, progress, evidence references, and next steps. The model chooses the notes' contents and wording; the extension manages storage, capacity, and resets.

For both explicit and automatic resets, rebuild active context from Pi's current system instructions, normal session/environment setup, latest notes, and history-recovery guidance. Remove conversational messages already presented to the model and the outgoing assistant response and tool calls/results. Keep these originals searchable and readable. User input not yet presented to the model, including input queued during tools or a reset, must survive and follow Pi's normal input-queue rules. New messages and tool results accumulate normally. Goals and corrections from removed messages are recovered through notes or history.

Finish every tool call in the current model response before resetting, including calls alongside `new_context()`. Archive their calls/results in the outgoing window and use the final successfully saved notes after the batch finishes. Continue automatically in the same session, preserving workspace files, without another user prompt or a separate model/provider compaction call to generate a summary.

Expose `notes_write(text)`, `notes_read()`, `new_context()`, `history_search(query)`, and `history_read(window_id, item_id)` as model tools. Notes writes replace the entire value. Overlapping writes must act as complete replacements in a documented order, respecting writes that already succeeded before another began. Both reset routes must work before any notes exist and after `notes_write("")` clears them, using the same context rules without restoring old notes or substituting a generated summary. Reopening the session must preserve its notes (including an empty value), active context, and access to history. Separate sessions keep notes and histories independent.

Reuse Pi's extension flag system for `--context-reminder-tokens`, `--context-rollover-tokens`, and `--context-response-headroom`, accepting positive integer token counts. Reminder must be below rollover; headroom must be below the model's capacity. Document defaults. Count full current-window input using Pi's existing `estimateTokens` semantics: sum the active messages, including carried notes and new tool output, and add the text estimate of the effective system prompt followed by a newline and JSON of active tool definitions (`name`, `description`, `parameters`). Equivalent calculations are allowed. Exclude removed windows; do not use cumulative session usage. Cap rollover at full model capacity minus response headroom. Rollover triggers a reset; it is not a hard limit on the rebuilt input. After resetting, allow the required request if the full fresh input is below the current model’s capacity minus response headroom, even when it is at or above rollover. Do not repeatedly reset the same pending request. If fresh setup, notes or unpresented input reaches or exceeds that model input budget, report an error without discarding it or sending an oversized request. Reevaluate this budget using the current model on subsequent required requests, so switching to a sufficiently larger model allows recovery without raising the configured rollover.

Check capacity before a model request required by normal Pi execution: tool continuation, pending input, or a new user turn after an idle period. At or above the reminder threshold but below rollover, remind the model once per window of remaining capacity and the need to save notes. Use Pi's custom-message mechanism with `customType: "context_capacity_reminder"`; its model-visible JSON text contains a nonnegative integer `remaining_tokens` and a `message` advising the model to save notes. Wording is unrestricted. At or above rollover in the outgoing window, reset before the request, whether or not notes were saved; rollover takes precedence over a reminder. Reminders and capacity checks must not themselves start requests or prolong an otherwise finished turn. `new_context()` explicitly requests a reset and continuation. No task-completion inference is required.

Return JSON text from these tools. Note/history reads include the complete `text`; search returns `items` with opaque, stable, session-scoped `window_id` and `item_id` values. The former identifies the record's context window and the latter its record within that window; pass them unchanged to `history_read`. A complete search response omits `next_cursor` or sets it to null. If results are paginated, return a non-null opaque `next_cursor` and accept it unchanged as `history_search({query, cursor})` with the same query. Traversal must reach all matches without newly appended search/read calls shifting older pages. Other fields, optional arguments, ID encoding, page sizes, and search-result ordering are implementation choices.

History search uses case-sensitive literal substring matching over conversational text, including user messages, assistant visible text and reasoning, and tool results; semantic search is unnecessary. An empty query browses earlier records without a remembered keyword. Matching originals must remain discoverable across repeated resets and reopening, including through any documented result limits or pagination. Retrieve selected records without reloading the entire history. A history read's `text` may be original text or lossless JSON containing the complete original record; escaping is allowed, but summaries, truncation, or rewritten evidence are not.

Work in `/workspace/pi` with the installed dependencies and deliver code and documentation covering activation, configuration, and model usage. Pi runs directly from TypeScript source. Existing provider/catalog errors in `npm run check` are unrelated to this task.
