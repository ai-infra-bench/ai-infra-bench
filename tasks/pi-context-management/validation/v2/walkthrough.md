# 一起 review：一次上下文切换

这条记录来自正式 Harbor 的参考实现 `rollover` 场景，模型输出是确定性脚本，Pi 的工具执行、上下文和历史都是真实组件。

1. 模型读取目标日志和一份无关日志，产生一个待验证的假设。
2. 模型写下工作笔记：缓存已排除，继续检查连接池。
3. 模型调用 `new_context`。
4. 第 4 次真实模型请求保留目标、系统指令和笔记，移除了旧假设、两份原始日志及之前的工具调用/结果。
5. 模型在新窗口调用一个普通工具；第 5 次请求正常包含新消息及配对的工具结果。
6. 模型搜索旧证据线索，再用返回的 ID 读取原始记录。第 7 次请求重新包含目标记录中的原始凭据，但没有重新载入无关日志。

先看这个区别：`new_context` 返回成功只是请求被接受；第 4 次发给模型的实际输入，才证明切换发生了。随后第 7 次请求证明原始证据仍能找回。

另一个值得一起看的场景是 `batch`：同一批调用先请求切换，再执行外部工具、更新笔记、再次请求切换。下一次请求必须带最新笔记，批内工具各执行一次，批内消息仍退出工作上下文。

精确请求编号、随机笔记值和观测结果在 `walkthrough.json`；完整原始请求保存在 artifacts/pi-context-hardening-20260914/remote/jobs 下。
