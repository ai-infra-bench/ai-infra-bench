# Verifier QA matrix

Every case runs through the same entrypoint CI uses (`.github/scripts/task_ci.py`
`validate` / `image-check` / `prepare-case` / `check-result` around
`harbor run`, Harbor 0.22.0). Controls are the Oracle with one deliberate
defect, generated by a curator script from the Oracle source so that each
patch is a full, self-contained diff against Base (`validation/ci-cases.json`
pins their SHA-256).

| Case | Defect | Expected | Rejecting layer |
|---|---|---|---|
| base | no extension | 0 | contract 15/15 fail (no trace file), lifecycle 2/2 fail; PASS_TO_PASS passes on Base |
| oracle | reference implementation | 1 | all layers pass |
| control-int-attributes-as-numbers | `intValue` encoded as a JSON number instead of the OTLP/JSON decimal string | 0 | every case (strict OTLP/JSON parse) |
| control-chat-written-before-persist | chat spans written at `message_end`, before pi persists the assistant entry, so they carry no entry id | 0 | every case (bijection with the branch) |
| control-trace-id-per-process | random trace id per extension instance | 0 | reload case + lifecycle |
| control-wakeup-as-prompt | every non-continuation run reported as `prompt` | 0 | triggers case (a prompt run must reference a user entry) + compaction case |
| control-continuation-as-wakeup | `agent_settled` not tracked | 0 | triggers case + compaction case |
| control-tool-error-status-ok | failing tool result keeps status OK | 0 | errors case |
| control-compaction-under-last-run | compaction spans parented to the run that just ended | 0 | compaction case (a child cannot end after its parent) + lifecycle |
| control-missing-line-terminator | lines appended without `\n` | 0 | every case (the file is not JSON Lines) |
| control-error-status-without-message | ERROR statuses carry no message | 0 | errors case |
| control-chat-held-until-turn-end | the chat span is written only at `turn_end` | 0 | lifecycle kill case (the interrupted turn's chat span is missing) |
| control-no-shutdown-flush | `session_shutdown` discards open spans | 0 | shutdown case (empty file) |
| control-write-failure-throws | a failed write throws out of the handler | 0 | unwritable-path case (pi's error listener sees the exception, no report) |
| control-aborted-as-ok | aborted assistant messages leave chat and turn OK | 0 | abort case |
| control-no-start-lines | spans written only when they end | 0 | live case, kill case, and every case's pairing check (end lines without start lines) |
| control-end-line-keeps-phase | end lines keep `pi.span.phase = start` | 0 | every case (strict parse: an end line must not carry the phase) |
| control-single-tool-slot | one tool span tracked at a time | 0 | parallel-tools case (a span lost, tool_call_count and the bijection off) |
| control-steer-messages-unrecorded | steering messages not listed on the run | 0 | steering case and its bijection (user entries unreferenced) |
| control-compaction-usage-omitted | compaction spans omit the summary usage | 0 | compaction case |
| control-no-trace-propagation | the Oracle's propagation variable neither read nor published | 0 | sub-agent case (the child's file has a different trace id and no parent) |
| control-retry-run-claims-a-message | the overflow retry run resolves an entry id like other runs | 0 | overflow case (the retry run claims the unrelated custom message; bijection) |
| control-overflow-will-retry-false | `will_retry` always false | 0 | overflow case |
| control-forged-junit | writes a passing contract JUnit to `/logs/verifier` then `process.exit(0)` | 0 | vitest exit status + lifecycle (child processes die before reporting) |
| control-process-exit-zero-after-registration | `process.exit(0)` 50 ms after the extension loads | 0 | vitest exit status / empty JUnit inventory |
| alt-grok-run3 / alt-grok-run4 | grok-4.6 rollouts 3 and 4 (task 0.0.3), unmodified | **0** under 0.0.4 (were 1 under 0.0.3) | both scored 0 in the rollout only because the shutdown case required the three closing spans to share one nanosecond timestamp while these implementations read the clock per span (1 to 2 ms apart); the assertion now brackets the shutdown with the verifier's own clock (every close inside the dispose window, child-first order), and both passed every 0.0.3 layer; under 0.0.4 each fails exactly the two new cases (overflow recovery, sub-agent propagation), the evidence that those edges discriminate |
| alt-grok-run5 | grok-4.6 rollout 5 (task 0.0.4), unmodified | **1** | the first 0.0.4 rollout passed every layer, including overflow recovery and sub-agent propagation (class-based state machine, a parsed `PI_AGENT_TRACE_PARENT`, the same publish-while-running rule) |
| alt-grok-run1 | grok-4.6 rollout 1 submission (task 0.0.1), unmodified | 0 | passed every 0.0.1 layer once the verifier's millisecond-clock assumption was removed; under 0.0.2 it writes no start lines, so every case's pairing check rejects it, and it also misses the shutdown, unwritable-path and kill cases |
