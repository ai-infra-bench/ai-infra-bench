# 从用户提供的 #75 session 提炼的 review 方法

它的重点不是增加测试数量，而是建立可证伪的证据链：**题面承诺 → 合法触发条件 → 真实执行路径 → 外部可观察结果 → reward**。Oracle 和现有测试都只是待审对象。

1. **冻结范围和身份。** 先记录题面、Base、镜像、补丁、测试和 skill 的实际哈希；区分任务审查、实现审查、轨迹审查。历史 PR 提供线索，不自动扩充契约。
2. **先读题面，再读答案。** 从使用者承诺推导输入边界；题面应像开发需求，清楚但不泄露实现。不能为了维护 Oracle，把其私有约定补进题面。
3. **画出必须真实运行的边界。** 状态、时序、基数、对应关系或生命周期由哪个组件决定，就执行哪个组件。允许替换边界外的生产者，但记录替换理由；“端到端”这个标签不能代替实际路径证据。
4. **双向检查。** 从需求向测试看遗漏，从每个扣分断言向需求看额外限制。最终输出正确，不自动证明异步、持久化、预算归属或协议配对正确。
5. **主动挑战而非仅验收。** 分别找“错误实现获满分”和“正确行为被扣分”的小反例。Oracle 至少接受一次从题面独立推导的挑战；正确替代实现也不能仅凭得分证明正确。
6. **验证反例是否合法、为何失败。** 经过真实生命周期，观察最终请求或结果；排除非法 fixture、缺依赖、陈旧 bundle、错误报告格式等替代解释。观察者不能替候选修复缺陷。
7. **检查环境与评分信任边界。** 核查 agent 可见内容、cutoff、依赖和资源；区分加载候选代码、计算期望、写报告、决定 reward 的进程和权限。只声称实际证明的防绕过范围。
8. **小反例稳定后再做完整验收。** 修复须保留旧错误对照，并更新映射；按变更范围复验。正式入口、归档、哈希及原始日志齐全后才称完成，不反复盲跑大矩阵。

套到模型迁移题：必须真实执行 Session Controller、AgentLoop、SDK 序列化、工具与持久化恢复；固定 HTTP/SSE 可以替代模型推理计算。应检查历史是否真正进入迁移后的请求，而不能只看生成了一份正确报告。对于错误文案、辅助函数和存储中间表示，则要明确哪些是公共契约、哪些只是当前 Oracle 的选择。

本轮按 review 模式执行：新增独立探针和证据；不修改正式题面、Oracle、verifier 或历史模型得分，不启动新的被测模型轨迹。
