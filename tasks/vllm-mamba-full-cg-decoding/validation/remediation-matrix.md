# Review remediation

The task statement is unchanged. It asks for correct Mamba FULL-CG output and recurrent-state updates while preserving genuine first-token prompts, eager execution, ordinary decode and supported speculative decoding. It does not prescribe a repair location, metadata representation, placeholder value or no-sync policy during input preparation.

The tested path is: ordinary generation requests and existing state → production scheduling, input preparation, backend selection, recurrent kernels and CUDA graph replay → subsequent generated tokens and complete output distributions. Local chunked prefill produces the same prior-state continuation needed by the original disaggregated-serving bug. The actual NIXL network transfer is outside this local validation boundary. All checkpoints are small real models constructed during verification, outside the agent image.

| Contract behavior | Grading workload |
| --- | --- |
| Correct FULL-CG continuation | Mamba1 and Mamba2 with final single-token prefill chunks, multiple batches and real CUDA graph launches. |
| Genuine first-token and multi-token prefill remain correct | Hybrid Mamba2 with a fresh 3-token prompt, a 19-token prompt split with a budget of 16, and mixed requests under two speculative tokens. Output is compared with an independent non-speculative eager reference. |
| Request/state identity survives lifecycle changes | A four-row captured graph with fewer live requests, cancellation of a partial prefill, removal of another request and completion of the surviving requests. All survivor tokens are checked. |
| Supported speculative state remains continuous | Hybrid Mamba2 with naturally accepted drafts followed by a zero-draft step, including partial acceptance; compare every returned token and logprob vector with non-speculative eager. |
| Existing cache/speculative combination remains correct | The supported hybrid all-cache mode, repeated shared prefixes, partial acceptance and subsequent decode; the selected fixture also passes unmodified Base eager with caching enabled. |
| Eager remains usable | Dedicated Mamba1 and Mamba2 ordinary eager cases plus hybrid speculative eager. |

The reference is immutable Base code extracted before candidate imports and executed in a root-only source directory. It uses eager inference without speculative decoding. Using Base eager with the same speculative configuration would allow a shared speculative-state defect to pass unnoticed. Candidate code only executes as the unprivileged agent, and it cannot read reference outputs or private logs.

A separate, non-dumpable native observer watches the root-owned CUDA driver through hardware execution breakpoints. It observes both entry and successful return from graph-launch APIs during the generation window after model initialization. A failed CUDA call does not count. Candidate stdout is sent to a diagnostic log, and candidate access to the observer's report pipe and memory is denied by process permissions. The scorer reads these independent observations, never a candidate-provided graph counter. Public speculative metrics are retained as workload observations; correctness still comes from the independent numeric comparisons. This instrumentation is execution evidence, not a proof against arbitrary native-runtime or whole-program rewrites.

Correct controls retain different repair locations: production backend builders, runner inputs, a shared split operation and a host read during preparation. Incorrect controls cover old reference patches, missing padding cleanup, missing multi-token prefill protection, a missing accepted-state offset on zero-draft steps, state-address corruption, eager/speculative breakage, successful early exits, forged output reports, forged profiler data, failed driver calls and attempted access to private reference results.

The revised reference patch adds three corrections to the earlier Oracle: padding rows cannot become phantom prefills; multi-token prompt chunks cannot accidentally enter a decode-only graph; and Mamba2 receives the previous accepted-token offset even when the current step has no drafts. Stateful one-token extensions still use the existing decode/update path.

Diagnostic observations were kept separate from grading. The first padding probe collected no rows because it confused internal and external request IDs; the final test matches complete survivor outputs by the supplied prompts. Pure Mamba2 does not maintain the same speculative accounting as hybrid models at this Base, so supported hybrid Mamba2 is used for speculative regression. Very small all-cache geometries exposed an independent Base buffer-sizing issue, and a two-token cached suffix differed even under unmodified Base non-speculative eager. Those are not silently added as new repair requirements. The graded all-cache fixture has an independently passing Base eager baseline. Later PD speculative-padding and fused-copy features remain outside the frozen task.

Mamba1 logprobs use an absolute tolerance of 4e-5; Mamba2 and the hybrid model use 8e-3 with no relative tolerance. The frozen float32 SSD kernel tests allow 8e-3 absolute plus 5e-3 relative, so the allowance is independent of the reference patch. Correct alternatives and targeted state-corruption controls calibrate the tested numerical distinction. Exact final outcomes and artifact hashes belong in e2e-evidence.json; historical matrices are not substitutes for the current run.
