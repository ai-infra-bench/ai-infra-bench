# v0.0.3 行为测试设计

目标是检验并行子 agent 能在结束前互相获得信息。新版题面允许各实现设计自己的接口，因此测试分为两部分：审查者编写的公开接口适配，以及所有实现共用的行为观测。适配文件不由被测实现提供，不读取实现的队列或替它注入消息。

最小新增实验 `use_finding`：A 的外部调查工具返回随机生成的 API 路径，B 的工具正在运行。A 发送成功返回以后，才释放 B 的工具。检查 B 下一次实际模型请求包含完整内容、正确发送者，且仅一份。脚本模型从这次实际请求中提取路径，再通过 B 的工具调用本地 API；服务端验证路径，返回 200 或 404。B 的工具结果不包含路径，测试也不会给 B 提前提供答案。

模型回复由脚本产生，Pi 的父/子进程、通信工具、传输、队列、上下文注入和工具执行都真实运行。这个用例证明执行链可用，不声称真实模型会自行选择正确行动。另行让 G6 根据题面编写实现，是解题试跑，不是让 G6 扮演这里的 A/B。

现有 18 项场景调整如下：删除题面不再要求的“固定调用者 ID 必填/唯一”测试，加入 use_finding。长 Unicode 场景改为普通短 Unicode 消息，不再要求至少支持 16 KiB。成员状态返回值不限定枚举；无效请求允许明确的拒绝结果或工具错误。调用名称与参数、返回结构通过独立 binding 翻译；发给模型的上下文原文不经过该翻译。

仍保留普通 single/parallel/chain、私信、广播、顺序、Unicode、结束边界、未知/自身/已结束/未启动目标、无效输入、非目标隔离、并行团队隔离、连续团队复用、取消。

正确对照使用 JSONL 存储，同时将 communication 改为 collaborate、team_members/team_send 改为 colleagues/share、to 改为 recipient、accepted/failed 改为 queued/rejected。它通过同一套行为测试，适配层只映射公开调用。三个错误对照分别丢失、重复和倒序送达。

G6 试跑前冻结新版题面、测试主线和原始输入。解题结束后审查其公开文档、工具 schema，编写对应 binding，再冻结该 binding 后评分。不得按失败结果反改行为要求，或让 binding 实现实际通信。评分器中任何独立发现的误判必须另记修订前后版本与原因。

限制：任意新接口目前需要人工接入与审查，尚未实现对任意提交自动推导 binding；这不是完整发布审核。正式评分也不能把缺少适配器误记为模型实现失败。原 v0.0.2 的模型分数不属于本次试跑。
