# 本轮重评的边界

本轮复评原有 G6、G56 各 4 份提交，不重新解题，也不修改模型提交。新增派生补丁只用作独立测试对照，不计入 pass@4。

## 为什么需要适配

v0.0.8 的默认广播故障通过移除 C 文件信箱的写权限实现。原始八份模型提交使用进程内队列、TCP、Unix socket 或 RPC，因此不能把默认配置的“不支持此传输”算作模型错误。

- G6 #1–#4：每条消息上限 64 KiB，队列上限 1 MiB。让 C 执行尚未完成的外部工作，通过 A 的真实公开发送工具向 C 连续发送 16 条 64 KiB 消息。逐条核实接受结果，然后广播新的 finding。B 的队列仍为空；C 的队列已满。要求接受 B、明确报告 C 失败，B 的下一次模型输入包含完整 finding。没有直接写入或读取候选队列。
- G56 #1：每条消息上限 256 KiB，TCP 持久连接。通过 C 实际连接的端口定位父进程对应的 socket。
- G56 #2、#4：每条消息上限 64 KiB，父进程经子进程 stdin 发送 RPC。通过已观测的 C 进程 PID 定位对应 stdin socketpair。
- G56 #3：每条消息上限 128 KiB，Unix socket。通过 SO_PEERCRED 定位 C 对应的连接。

对三个连接传输配置，在候选准备向所选 C 连接写入真实 finding 时，fixture 对该 OS 连接执行 SHUT_WR，然后调用原始 write。没有伪造工具返回值或错误字符串，也没有替候选补上错误处理。该时刻广播已经选择收件人，因此不能把 C 提前从 roster 消失混同于一次部分发送失败。B 的连接不受影响。

允许发生连接故障的 C 退出；题面明确排除 crash recovery。仍要求原始广播报告 C 失败，健康的 A、B 完成双向交换、父进程正常收尾、全部子进程退出。对于 C 还能继续调用模型的情况，仍检查其没有收到失败的 finding。

## 观测修正

初版故障事件采用异步 HTTP 上报。RPC 候选因未处理的 EPIPE 立即崩溃，事件来不及送出；尽管 stderr 已保留真实 write EPIPE，测试还错误地附带“故障未执行”。最终版本在 SHUT_WR 成功后同步记录事件，再执行原始 write。同步记录不处理候选的 EPIPE，也不修复其通信。

G56 #3 超限时实际返回 `Message is 131073 bytes; maximum supported size is 131072 bytes.`。旧的公开结果适配器只认识空消息错误，未识别这条明确拒绝。最终适配器识别该公开返回格式；消息上限与实现代码保持一致。原候选补丁没有变化。

## 对照与复现

- 原 Oracle、改名 JSONL 实现：检查扩展后的 verifier 没有破坏已有正确路径。
- IPC、Unix socket 各一份“仅隐瞒广播失败”实现：应仅在 broadcast_partial 失败。
- 由 G56 #4 派生的错误处理对照：只增加 stdin 的 error 监听，将错误交回已有 RPC 拒绝路径。用于检查同一真实 OS 故障可以被正确处理；不计作模型成功样本。
- 直接伪造 reward 和提前退出：通过正式 Harbor 入口重新检查评分隔离。

最终评分应仅引用 `grades-v9` / `grade-jobs-v9` 的冻结运行，不将初版适配结果或中间修正结果混入。每个结果必须核对实际执行的 tests、task.toml、题面、补丁和适配器哈希。

## 限制

脚本提供模型输出，但父子 Pi、发送工具、IPC/socket/RPC、队列、模型输入构建与进程生命周期都真实执行。本轮不证明真实模型会主动分享发现，或分享会提高任务成功率。

取消测试对这些实现观察进程退出，结合已审查的进程内消息存储方式判断待处理消息随进程消失；连续团队测试观察父进程监听器和活跃句柄增长。这不是任意资源泄漏的完备证明，也不对普通日志或空目录扣分。任意新实现仍需审核接口与场景适配。

最终对照还排除了一种测试误报：正确处理连接失败的 RPC 实现会让 C 退出；测试服务器向已退出 C 的 `/work` 请求返回结果时可能出现 BrokenPipeError。最终 verifier 仅在广播故障已实际触发、请求确为 C 的外部工具请求且错误是连接关闭时记录诊断，不计作模型错误。所有行为断言、A/B 请求错误、父进程异常退出和子进程存活检查都保留。再次对统一冻结版本执行完整 15 项矩阵；最终结果来自 `grades-v9b` / `grade-jobs-v9b`，前面的 `grades-v9` 也属于调试证据，不计入最终统计。
