# 评分器并发假设修正

原始反例和原始得分保存在 ../v3/G56-REPORT.md 与 g56-failure-audit.json。题面未规定开启通信时最多四个 worker。旧 pending_recipient 却直接把 E 当作未运行，在 E 实际运行时仍要求拒收，这是无依据限制。

新版将该项替换为 five_workers_private：父进程创建五个同名 agent 实例，A 向 B 发送私信并收到回复，C、D、E 执行独立工作。观察真实模型输入，要求 B 下一轮收到且使用完整消息，其他三者不收到，所有真实子进程正常结束。测试不再推断第几个任务必然排队，同时允许分批启动和同时启动。

未运行收件人不应接收的要求仍由已结束收件人和不存在收件人的场景覆盖；新版不宣称覆盖所有队列中、启动中状态。没有降低及时投递、顺序、隔离、取消等原有契约。

题面与环境逐字节不变；仅任务版本改为 0.0.4，评分代码改为上述场景。已有两份模型提交会从冻结补丁重新执行全部新版测试，旧版成绩不直接计入新统计。其余六份独立解题看到相同题面，没有任何测试或已有实现反馈。

正式结果和最终哈希在本目录 pass4-results.json 与 artifact-hashes.json 收集。完整发布审核不属于本次 pass@4 运行，仍不声称覆盖任意候选篡改评分器的情况。

## RPC 观察器修正（0.0.5）

独立地启动未修改 Base 的 RPC 模式，从 stdin 发送包含 ROLE:A 的任务；旧 fixture 只看 argv，且模型请求观察器要求 Task: 前缀，误把 A 识别成 ROOT，报 subagent tool failed to load。新版从实际 before_agent_start 的 prompt 绑定尚未知晓的身份，并取消 Task: 前缀假设；不修改任务输入或消息。相同独立探针修正后通过。

所有正式候选和对照重新运行 0.0.5；0.0.4 评分保存在 remote 的 grades-before-rpc、grade-jobs-before-rpc 及本地 checkpoint 归档，不混入最终统计。六个已经运行的求解会话没有更改题面、代码或反馈。
