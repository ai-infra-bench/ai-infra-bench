# Review report

Version 2.1.3 fixes cumulative-output handling in the coalesced-output alternative and adds the corresponding ordinary-generation regression. The complete grading matrix has 18/18 expected results: Oracle and five correct alternatives receive 1; Base and eleven negative controls receive 0. Each correct implementation completes 21 public behavior scenarios. A fresh Harbor Oracle receives reward 1 with zero errored trials. This validates the scoped scoring repair; the existing native ABI cutoff approximation remains a separate environment limitation.

The previous coalescing alternative appended every output frame with aggregate=True. This duplicated the already-generated prefix in ordinary CUMULATIVE mode and could mutate a live detokenizer token list. In the independent review, a four-token request returned 22 public token IDs despite receiving reward 1 from version 2.1.2. The corrected control copies the buffered public outputs, appends DELTA content, and replaces CUMULATIVE content. The old patch is retained unchanged as cumulative-output-duplication.patch with expected reward 0.

The verifier now runs ordinary requests before and after streaming in explicit DELTA mode and default CUMULATIVE mode. The latter omits output_kind from SamplingParams, exercising the public default. These requests generate eight tokens with EOS ignored and no explicit stops. Cumulative snapshots preserve previously returned prefixes and the final tokens and text match the independent model/tokenizer reference and the matching DELTA request. No fixed output frame size, minimum number of frames, or speed requirement is imposed. The corrected coalescing alternative demonstrates that one combined cumulative frame is accepted.

Oracle, the corrected coalescing alternative and the old defective control first ran through the targeted grading entrypoint. They then ran again in the full matrix with fresh reference weights. The old control now fails on ordinary_cumulative_before token comparison. The existing forged-report and early-success-exit controls remain in the full matrix; no candidate failure is retried. Correct full-entrypoint runs took 42.53–44.83 seconds, averaging 43.28 seconds on one A100 per evaluation.

The eight input-adapter tests and two reference-workload tests pass. The reference-workload tests now also verify that the ordinary DELTA and CUMULATIVE requests share their expected complete output. The task statement, Oracle, production lifecycle paths, delayed-input completion convention and environment are unchanged.

Harbor uses the documented one-GPU Docker adapter and the pinned task image. A task-local executable copy fixed setup; the final job pr71-cumulative-output-oracle-final, trial harbor-task__eLXLyA4, completed with reward 1 and zero errors. Version 2.1.2 documentation is retained under history/2.1.2-before-cumulative-output/. The final strict artifact audit passes all five checks with zero errors and warnings, including image identity and applicability of all 17 solution/control patches.
