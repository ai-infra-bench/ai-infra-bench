| --- | --- |

The semantic boundary is processor-produced token/range pairs → request admission or continuation → real Request, Scheduler, encoder ownership, and KV cache lifecycle → returned tokens, object release, and actual cached-token counts. The frozen Qwen processor was executed to establish input reachability. Recorded token/range pairs preserve its constraints during scoring. Fixed media shapes and sampled token IDs substitute for model computation; no full Qwen model, HTTP server, GPU kernel, or output-accuracy comparison is claimed. Expected reuse comes from computed full blocks and the first changed input, never from Oracle-generated hash values. The scorer does not require media offsets in a hash or arbitrary independent mutation of related fields.

## Reference and controls

The unchanged reference avoids binding the request into its own callback, rebuilds streaming identities after replacement, scans all relevant media, and distinguishes media boundaries. It also includes relative offsets in its hashes; that representation is optional for the scored workflow. The alternative preserves Base's bound callback while the request is live and releases it at the real completion boundary; it receives the same cache checks. A renamed-private-helper control checks that the verifier does not depend on that scheduler helper's name.

The previous task Oracle is retained as `old-oracle.patch`. `last-media-only.patch` and `media-boundary.patch` each restore a scored cache defect while retaining the other reference fixes. The former `media-position-alias.patch` is now `no-media-offset.patch`, a positive representation control: its omission of offsets must not fail these supported Qwen cases. This is scoped coverage, not a claim that offsets are unnecessary for every multimodal model or API. `stream-stale.patch` restores stale streaming identities while retaining the lifecycle and media fixes. Existing partial-lifecycle, forced-GC, fake-hash, forged-report, and early-success-exit controls remain. Outcomes must be recorded against final patch and verifier hashes; previous passing rollouts do not validate this revision.

Raw logs and upstream snapshots belong in the external evidence ZIP, not this task directory. The evidence index identifies the checked artifacts, results, scope, and archive checksum.

## Input reachability evidence

Task 1.5.0 follows the rubric at skill commit `a7b98ef` (PR #89), loaded from `/tmp/ai-infra-task-fixture-reachability`. The instruction and image are unchanged. The previous `[77] * 33` fixture with independently moved image ranges was a curator-generated internal probe, not an upstream product reproduction. It is not a valid basis for grading this Qwen workflow: the real processor produces image placeholder ID `151655`, media lengths from the processed image grid, and positions tied to the prompt. This does not claim that all position collisions in every model are impossible.

`validation/generate_qwen_inputs.py` runs Base's real `MULTIMODAL_REGISTRY.create_processor(...).apply(...)`, including the real Qwen tokenizer and image processor, on ordinary text and generated red, blue, or green 56×56 images. The pinned model resources are from `Qwen/Qwen2.5-VL-3B-Instruct` revision `66285546d2b821cf421d4f5eb2576359d3770cd3` (2025-04-06, before cutoff). File hashes are in `validation/input-provenance.json`. No weights or GPU are needed. Mount those processor resources at `/tmp/qwen-processor` and run the generator in the task image with `--model /tmp/qwen-processor --output <file>`. Base includes the model path in media hashes, so use this same container path for byte-identical output. Its output must match `tests/qwen_inputs.json` byte-for-byte. These resources were used only for curator validation; no task-specific reproducer enters the agent image.

The recorded single-image input has eight tokens and an image range at offset 1 with length 4. Multi-image cases use 16- and 32-token blocks. Partial prompts have 31 or 63 tokens; two complete images share the last unfinished block. Boundary prompts have 33 or 65 tokens; the second image ends at the preceding block boundary and is followed by the real vision-end token. Changing image content preserves token IDs but changes its media identity. Inserting ordinary text between images changes both token IDs and the second range's offset. Repeated images use the same real media hash. These relationships were checked during generation, not inferred from an Oracle pass. Generation also verifies fresh token-input requests containing an appended output suffix through the real processor; their final token IDs and media ranges match the recorded prompt plus that suffix.

Lifecycle and memory tests reuse the single-image token/range shape. Text-token changes stay outside its media range; streamed text chunks use ordinary vocabulary IDs, and the sampled end token is Qwen's `151645`. Streaming transitions use Base's actual scheduler, which discards the uncomputed sampled token and offsets any newly added media. Request payload data is replaced with page-touched buffers to amplify ownership retention for external RSS measurement; the model registry provides the verified media token cardinality. Pixel computation and model output quality are not evaluated, and the buffer size is an observation workload rather than a claim about the captured image tensor's size.

An independent validation-only challenge starts with one processed image, waits for streaming input, adds a second processed image, then finishes. With 8-token blocks it checks 16 reused tokens for the matching request, zero when the first image changes, and eight when only the newly added image changes. Oracle and the alternative pass without fixture-side cache insertion or hash repair.
