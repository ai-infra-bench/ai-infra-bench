# Behavioral contract and coverage

The semantic boundary is: resolved configuration and plugin selection → real factory dispatch or worker lifecycle transition → constructor arguments, instance identity, callbacks and propagated errors. These components run from the candidate's vLLM source. The external connector implementation is controlled input; its abstract transfer methods are no-ops because no KV transfer or model execution determines constructor semantics. GPU and model execution are outside this task.

| Developer requirement | Observation and exercised cases |
| --- | --- |
| Current connectors receive the same resolved configuration | At the plugin constructor boundary, compare the received object by identity with the engine-side object. Two different nonempty configurations contain a real attention layout, tensor and group; block counts vary per run. Both SCHEDULER and WORKER are exercised. |
| Current plugins, including inheritance and forwarding, still work | Explicit, inherited, defaulted and `*args, **kwargs` constructors run through the public factory. A registered inherited plugin exercises lazy registry lookup in both roles. The returned instance and public role agree with the constructor callback. |
| One invocation per connector creation | Each factory operation produces one constructor callback and returns that instance. Failing plugins also produce exactly one callback. |
| An active worker is reused; shutdown closes it; a new lifecycle gets a fresh instance and configuration | Real initialize → repeated initialize → shutdown → repeated shutdown → initialize with another configuration → shutdown. Observe public group access and plugin shutdown callbacks, without reading lifecycle globals. |
| Normal binding errors remain distinguishable | A current constructor has an additional required keyword-only `transport` argument. Python raises TypeError mentioning that argument before the body runs; this case is not a request to support keyword-only cache configuration. |
| Internal errors propagate without compatibility retries | Current plugins raise TypeError, ValueError and RuntimeError with fresh messages, in both roles. Check exception type, message and exactly one invocation. |
| Reject retired construction before initialization, with useful guidance | The two-argument plugin body must not execute. Diagnostic checks accept migration concepts rather than a fixture class name or exact parameter spelling. Positive controls use equivalent prose and a different exception type; the statement does not prescribe a diagnostic class. |
| Remove the retired base API too | Omission of cache configuration at the base-constructor boundary must fail, for both roles. No signature shape or private sentinel representation is required. |
| Required behavior must actually be checked before reward | The parent issues a fresh operation ID, verifies each response and evaluates each behavioral assertion. Bare early exits and forged stdout cannot complete the exchange. An additional control speaks the correct transport/envelope format but returns no constructor observations; it must fail the behavior check, not a report-format check. |

All reward-affecting assertions map to the rows above. The scorer does not read control patches or compare candidate source with Oracle source. Its independent alternative uses `inspect.Signature.bind`, preserves the original lookup helper and checks omitted base configuration with a sentinel; the Oracle uses signature capability detection and a required argument. Both are judged at the same public boundaries.

The IPC adapter necessarily observes Python object identity and callbacks inside the candidate process. The root parent owns the assertions and lifecycle sequence; the child reports operation observations, never pass/fail decisions. This removes the demonstrated marker/early-exit bypass. It is not a claim that executing arbitrary malicious Python and native code can be made tamper-proof by a JSON protocol.
