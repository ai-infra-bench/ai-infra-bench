# Behavioral boundary

Configured layer and changing ambient context -> real FusedMoE construction, modular factory/apply, local Triton experts and workspace lifecycle -> diagnostic behavior, expert outputs and profiling capacity. Configuration binding, allocation and expert computation are semantic and execute for real. Loaded weights, router outputs and a rank-ordered activation buffer substitute only input production; cross-rank transport is outside this configuration task.

The fixture preserves production expert partitioning, global-to-local maps and per-engine token counts. A supported scheduler budget of 16,384 tokens permits the later full routing window. Each owner/construction state starts in a fresh process to expose a cold missing reservation. The same factory result then spans matching, absent and conflicting profile/forward contexts. An additional same-process A/B/A sequence checks two owners without clearing their shared buffers. A cold ordinary owner must not reserve the DP+EP worst-case workspace; a later ordinary call may reuse an arena already enlarged by a DP+EP owner. The always-DP reservation control distinguishes those situations.

Immediately after the first cold absent/conflicting profile, the same layer executes a real 16,384-row forward under that context. The first transition's warning capture spans both calls, so its profile-gap/conflict label identifies the transition envelope rather than proving which of the two calls emitted a warning; the control patch and call trace establish that attribution. Repeated input classes let the independent parent check min/max outputs over every repeated row without transferring redundant large JSON tensors. The standard backend's two major routing intermediates are larger than the caller-owned output for these geometries. For this one-chunk standard path, _allocate_buffers reuses workspace13 for fused_out when it is large enough; an additional output-sized allocation is not a third independent intermediate requirement. Output-sized return tensors and smaller routing/weight temporaries are outside the reserved-workspace comparison.

The observer holds weak storage references and records simultaneous live-storage snapshots during real operations. It compares the profile capacity peak with the major workspace demand during the subsequent large forward. Aliased views count once; storage identity, buffer count, query count and persistent caching are not requirements. A packed arena and a per-call-release implementation are separate correct controls. Omitting only one major reservation is the targeted incorrect control. This is not a sum of all allocations ever observed: lifetimes and actual large-forward demand determine the comparison. The observer does not retain tensors, create candidate buffers or perform missing allocation work.

Independent challenge geometry uses eight experts, DP=EP=4, six input classes and different hidden/intermediate widths. Its cold conflicting-capacity subcase runs before any matching-context warmup in a separate process; it also returns to the original ordinary owner after a DP owner runs. No candidate cache is named or reset to create cold state.

The parent derives numerical references from its own operands; warning and memory observations still execute beside candidate code. Existing early-exit/report controls limit the supported integrity claim; neither process separation nor a passing Oracle proves resistance to arbitrary runtime modification. Raw historical scores, development failures and infrastructure errors are preserved separately from current acceptance evidence.

All formal and challenge factory inputs now use the real FusedMoE constructor. Rank discovery alone is supplied at the single-device transport boundary, using the owner’s configured rank and world size; the constructor derives effective topology and public properties. The explicit-override cases also use the real constructor. Two cold subprocesses construct the same ordinary TP=PCP=DP=1 layer under an ordinary engine and a DP=2/EP-enabled engine. The production factory and apply run through profile, forward and profile again. The parent checks independent numerics, warnings and equal observed peak storage across equivalent effective layer configurations; no byte constant, buffer name or storage layout is prescribed. The independent challenge uses engine DP=3, fresh geometry and real routing. Cross-rank transport remains outside this configuration task.

The factory result replaces layer.quant_method as in the production lifecycle. Weight loading copies into registered Parameters instead of replacing layer attributes. Both changes preserve normal layer interfaces for alternative implementations. Version 1.2.10 has CPU interface diagnostics only so far; earlier GPU evidence certifies 1.2.9, not this changed fixture.
