# Fixture reachability

The layer view carries consistent VllmConfig, FusedMoEConfig and FusedMoEParallelConfig. The real UnquantizedFusedMoEMethod constructor runs in the normal initialization context; the production factory and apply then execute after that temporary context ends or while another owner is current. Weight loading and routing are supplied as inputs and do not perform configuration resolution or workspace allocation for the candidate.

With TP=PCP=1 and DP=EP=2, production `determine_expert_map` gives ranks 0/1 experts [0,1]/[2,3]. The fixture selects only those local weights and supplies the actual global-to-local map. Four rank-ordered rows give engine counts [2,2]. The ordinary layer owns all four experts. Forward contexts use the real DPMetadata path; profiling uses its actual attn_metadata=None marker. NoEP preparation receives the already assembled activation buffer, so this fixture makes no network-transport claim.

SchedulerConfig explicitly permits 16,384 batched tokens and a 16,384 model length. The large formal forward has 16,384 assembled rows and [8192,8192] per-engine counts, within the supported budget. The fresh challenge has DP=EP=4 and [4096,4096,4096,4096] counts for its large forward, with [2,2,1,1] for its six-row probe. Thus the capacity transition does not depend on an impossible default scheduling budget.

Six cold owner/construction processes each retain one actual factory result across the transitions. The first gap/conflict profile is assessed before another state can fill a missing reservation. A separate A/B/A sequence preserves both instances and their shared cache, checking outputs and diagnostics after returning to the original layer. Ordinary cold capacity is compared across ambient states for the same implementation; a previously enlarged shared arena is not automatically classified as a wrong configuration.

Weak storage observation preserves allocation lifetimes. Simultaneous profile capacity is compared against real large-forward workspace demand, excluding caller-owned output and small non-workspace temporaries for the frozen backend geometry. Packed storage, views, and release after each call are permitted. No assertion depends on candidate-added attributes or requires one cache representation.

Explicit layer sizes are now produced by the real FusedMoE constructor, not by the layer-view fixture used for rank-local transport-boundary cases. Two cold subprocesses construct the same ordinary TP=PCP=DP=1 layer under an ordinary engine and a DP=2/EP-enabled engine. The production factory and apply run through profile, forward and profile again. The parent checks independent numerics, warnings and equal observed peak storage across equivalent effective layer configurations; no byte constant, buffer name or storage layout is prescribed. The independent challenge uses engine DP=3, fresh geometry and real routing. Cross-rank transport remains outside this configuration task.
