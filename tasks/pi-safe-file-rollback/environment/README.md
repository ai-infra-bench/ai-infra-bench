# Building and validating this task

`Dockerfile` is the frozen build recipe. `build/Dockerfile.template` records its
origin; no task-local regeneration command is supported. The obsolete generator,
builder and author-matrix runner depended on removed metadata fields and old
manifest formats. They have been removed. Use the checked-in Dockerfile through
normal Harbor/CI provisioning. Changes to actual build inputs require a reviewed
rebuild and updated input hashes in the minimal `image-manifest.json`.

Run the shared helpers from the benchmark repository root. With `ROLLBACK_IMAGE`
set to a retained image tag or immutable image ID:

```bash
python3 .github/scripts/task_ci.py validate pi-safe-file-rollback
python3 .github/scripts/task_ci.py env-key --task pi-safe-file-rollback --platform linux/amd64
python3 .github/scripts/task_ci.py image-check --task pi-safe-file-rollback --image "$ROLLBACK_IMAGE"
python3 .github/scripts/task_ci.py cases --task pi-safe-file-rollback
ROLLBACK_AGENT="$(python3 .github/scripts/task_ci.py prepare-case \
  --task pi-safe-file-rollback --image "$ROLLBACK_IMAGE" --case oracle \
  --output /tmp/rollback-prepared-oracle)"
harbor run --path /tmp/rollback-prepared-oracle --agent "$ROLLBACK_AGENT" \
  --env docker --jobs-dir /tmp/rollback-jobs --job-name oracle \
  --cpus limit --memory limit --override-cpus 4 --n-concurrent 1 --delete --yes
python3 .github/scripts/task_ci.py check-result \
  --result /tmp/rollback-jobs/oracle/result.json --expected-reward 1
```

Use a fresh output path and job name for each case. `cases` lists the declared
control names and expected rewards; use the corresponding value in `check-result`.
CPU CI uses four CPUs; the task still declares eight CPUs and 16 GiB memory.
`prepare-case` creates a CI copy with the full workspace archive disabled while
retaining the standard collection hook. Formal benchmark configurations keep the
full workspace archive.

Keep prepared tasks, Harbor results and generation records outside the source
task. Review `verifier-summary.json`, `pass-to-pass-summary.json`, both JUnit
reports and `behavior/behavior-results.json` with the collected reward. A static
validation result or successful process exit alone does not establish behavior.

The useful negative-control generator remains available. It requires a local Pi
repository containing the pinned Base object and never modifies that repository:

```bash
python3 tasks/pi-safe-file-rollback/validation/tools/generate_controls.py \
  --base-repo /path/to/pi --cases memory-only \
  --output-dir /tmp/rollback-control-generation
```

This command updates the selected control patches and their entries in
`validation/ci-cases.json`. It checks patch application and reconstructed source
identity, writes its provenance to the new external output directory, and
preserves unselected controls. Compile and run regenerated controls separately;
generation checks are not behavioral validation. The preserved historical Oracle
and correct alternatives are not generated by this helper.
